Root configuration

FilePurpose
.editorconfigCharset, indentation, final newline and trailing-whitespace rules that apply in any editor, including ones without Prettier installed.
.envYour machine-local configuration, created by copying .env.example.
.env.exampleThe documented list of every variable the framework understands, with safe defaults and no real values.
.gitignoreKeeps dependencies, run artifacts, saved sessions and secrets out of the repository: node_modules, test-results, reports, blob-report, playwright/.cache, storage/*.json, and every .env file except .env.example.
.nvmrcPins Node 22 (LTS).
.prettierignoreKeeps Prettier away from generated and vendored output: node_modules, dist, reports, test-results, playwright-report, blob-report, package-lock.json and screenshot snapshot folders.
.prettierrc.jsonFormatting rules: 100-character lines, single quotes, trailing commas, two-space indentation, LF endings.
eslint.config.mjsType-aware linting for the whole repository.
package.jsonDeclares dependencies, the Node engine range, the lint-staged rules and every command the team runs.
playwright.config.tsThe single entry point Playwright reads before anything else runs.
tsconfig.jsonCompiler settings and path aliases for the whole repository.

CI, containers and editor tooling

FilePurpose
.github/workflows/playwright.ymlThe GitHub Actions pipeline: a lint gate, a sharded three-browser test matrix, separate accessibility and visual jobs, and a final job that merges every shard into one HTML report.
.vscode/extensions.jsonPrompts new contributors to install the Playwright test runner, ESLint, Prettier and EditorConfig extensions.
.vscode/settings.jsonFormat on save with Prettier, ESLint auto-fix on save, the workspace TypeScript version, non-relative import suggestions (so the aliases are offered), Playwright browser reuse, and noise folders hidden from search.
docker-compose.ymlWraps the image with the environment variables, volume mounts and shared-memory settings a browser needs.
DockerfileBuilds a test image from the official Playwright base image pinned to the same version as @playwright/test, with browsers, system libraries and fonts already present.
MakefileA discoverable front door for the npm scripts.

Documentation tooling

FilePurpose
docs/README.mdExplains what each documentation output is, how to regenerate them, and how to add an entry for a new file.
scripts/docs/artifact.cssThe stylesheet for the hosted single-page manual, which has its own visual identity: IBM Plex Sans and Mono with Archivo for display, a cool slate ground and one ultramarine signal colour, plus full light, dark and system theme handling.
scripts/docs/build-docs.mjsMerges the authored content modules with docs/generated/api.json and writes the HTML documentation site into docs/site/, including the single-page print.html used to produce the PDF and artifact.html used for the hosted version.
scripts/docs/build-pdf.mjsOpens docs/site/print.html in the Chromium that ships with Playwright and prints it to docs/playwright-ui-framework-documentation.pdf with A4 pages, margins, and a header and footer carrying the document title and page numbers.
scripts/docs/content/The prose source of this documentation, split into modules by area: guides.mjs for the long-form pages, and files.*.mjs for the per-file reference.
scripts/docs/docs.cssThe single stylesheet for all three outputs: the screen layout (sidebar, tables, callouts, API blocks), the light and dark palettes, and the print sheet including the PDF cover page and page-break rules.
scripts/docs/extract-api.mjsWalks the repository and parses every TypeScript file with the TypeScript compiler API, recording exported classes, functions, interfaces, types, constants and re-exports along with their JSDoc summaries and public member signatures.
scripts/docs/highlight.mjsColours every code snippet at build time.
scripts/docs/render.mjsTurns the structured content blocks (paragraphs, lists, tables, code, callouts, step lists, trees) and the extracted API data into HTML.

Configuration (src/config)

FilePurpose
src/config/env.config.tsThe only file in the framework permitted to read process.env.
src/config/environments.tsStatic, non-secret settings for each environment — base URL, API URL, default retries and workers, and whether to ignore HTTPS errors.
src/config/timeouts.tsEvery wait in the framework references one of these named budgets — INSTANT, SHORT, MEDIUM, LONG, EXTRA_LONG, TEST, HOOK, EXPECT, POLL_INTERVAL, DEBOUNCE, ANIMATION — so tuning flakiness is a single-file change instead of a repo-wide hunt for magic numbers.

Form controls

src/components/form/multi-select.tsExtends Dropdown for controls that hold several values at once, usually rendered as removable chips.

src/components/form/select.tsNative <select> elements.

src/components/form/text-area.tsMulti-line fields.
src/components/form/text-input.tsSingle-line inputs of every flavour — text, email, password, number, tel, url, search — plus contenteditable fields.
src/components/form/toggle.tsSwitches: role="switch", styled checkboxes, or a pair of divs.

Data display

FilePurpose
src/components/data/card.tsCards and tiles — product cards, dashboard widgets, search results.
src/components/data/data-grid.tsExtends Table for enterprise grids — AG Grid, MUI DataGrid, Kendo, PrimeNG — which differ in three ways that matter: rows are role="row" divs, data loads asynchronously, and only the visible window exists in the DOM.
src/components/data/list.tsOrdered and unordered lists, role="list" and card collections: reading items, clicking by text or index, membership checks, index lookup and order verification.
src/components/data/pagination.tsPage controls: next, previous, first, last, a specific page, current page, total pages (from info text or the highest page link), page size, enabled state of the arrows, and forEachPage() for walking the whole set.
src/components/data/table.tsHTML tables, with everything addressable by column name rather than index: reading all rows as objects, single cells, whole columns, finding rows by criteria, clicking a control inside a matching row, sorting, verifying sort order, and row selection.
src/components/data/tree.tsTree views and file explorers: expanding and collapsing, walking a path of ancestors to a leaf, selection state, nesting level from aria-level, listing visible nodes and children.

Navigation

FilePurpose
src/components/navigation/accordion.tsCollapsible sections: expand, collapse, toggle, expansion state (via aria-expanded, the open attribute on details, or class names), section content, expand-all and collapse-all, and counting expanded sections to verify single-open behaviour.
src/components/navigation/breadcrumb.tsBreadcrumb trails: reading the trail, the current page, navigating to an ancestor, going up a number of levels, and depth.
src/components/navigation/link.tsAnchors, including the awkward parts: reading href and target, clicking and waiting for navigation, opening and returning a new tab, cheap reachability checking with a HEAD request, and internal-versus-external detection.
src/components/navigation/menu.tsNavigation menus, menubars and context menus, including nested submenus.
src/components/navigation/stepper.tsMulti-step wizards: next, back, finish, jumping to a step, current step number and name, all step names, completion and disabled state, and whether you are on the last step.
src/components/navigation/tabs.tsTab strips and their panels: selecting by name or index, reading the active tab and all tab names, disabled state, resolving the panel bound to a tab through aria-controls, and arrow-key navigation per the WAI-ARIA pattern.

Utilities (src/utils)

FilePurpose
